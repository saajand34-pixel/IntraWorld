<h1>CHAPTER 4: SYSTEM DESIGN</h1>

<h2>4.1 HIGH-LEVEL ARCHITECTURE</h2>
<p class=MsoNormal style="text-indent:0.5in;">
The architectural design of <strong>IntraWorld</strong> adopts a modern, three-tier cloud-native model structured around the principles of edge-computing intelligence, stateless client execution, and managed serverless database persistence. Traditional web architectures frequently suffer from severe bottlenecks because high-resolution image uploads and computer vision OCR workloads overwhelm central server CPUs and memory buffers. In contrast, IntraWorld distributes processing workloads efficiently across three architectural tiers:
</p>
<p class=MsoNormal>
<strong>1. Presentation &amp; Edge Intelligence Tier (Client Browser):</strong> Executing directly within the student's browser sandbox, this tier orchestrates user interactions, form validation, EXIF metadata correction, canvas-based image preprocessing, jsQR barcode decoding, and WebAssembly-powered Tesseract OCR neural parsing. Business logic&mdash;including acronym extraction, string distance heuristics, and field locking&mdash;executes on the client machine with zero server CPU consumption.
</p>
<p class=MsoNormal>
<strong>2. Gateway &amp; Perimeter Security Tier (External Distributed Gateways):</strong> This tier encompasses external perimeter defenses and transactional communication hubs. Cloudflare Turnstile provides reverse-proxy bot challenge verification; EmailJS/Web3Forms routes encrypted SMTP packets to Google Gmail servers; and the 2Factor Telecom Hub interacts with Indian cellular networks to dispatch SMS authentication tokens.
</p>
<p class=MsoNormal>
<strong>3. Persistence &amp; Governance Tier (Google Cloud Firestore):</strong> The backend consists of Google Cloud Firestore, a horizontally scalable, document-oriented NoSQL database. Firestore maintains collections for user credentials, pending registration queues, academic rosters, social feeds, and private messaging channels with automated real-time listener synchronization and strict declarative security rules.
</p>

<h2>4.5 USER INTERFACE (UI) WIREFRAME ARCHITECTURE</h2>
<p class=MsoNormal style="text-indent:0.5in;">
The user interface architecture is engineered following responsive, glassmorphic design principles featuring a deep-navy academic color palette (<code>#091226</code> and <code>#180206</code>) with high-contrast emerald green (<code>#10b981</code>) and amber (<code>#f59e0b</code>) accent states. The primary screen layouts encompass:
</p>
<p class=MsoNormal>
<strong>1. Registration Interface (<code>register.html</code>):</strong> Structured as a four-part progressive form containing Contact &amp; Identity, Manual College Information, Security Recovery Questions, ID Card Upload with dual OCR card, Cloudflare Challenge, and Password security.
</p>
<p class=MsoNormal>
<strong>2. Dual OCR Result Card View:</strong> Positioned in Section 4, this interactive component renders the card thumbnail, engine note (QR 100% vs. Neural OCR), locked Course and Roll Number inputs with padlock indicators, real-time college anti-cheat match badges, and the supervised manual edit override button.
</p>
<p class=MsoNormal>
<strong>3. Administrative Review Console (<code>admin-approval.html</code>):</strong> A restricted console featuring pending applicant summary cards, high-resolution ID card inspection modals, anti-cheat scores, and instant One-Click Approval or Rejection buttons.
</p>
<p class=MsoNormal>
<strong>4. Campus Feed Interface (<code>index.html</code> / <code>feed.html</code>):</strong> A multi-column dashboard featuring departmental filters, an authoring modal with study tag selector, like/comment threads, and trending campus topics.
</p>
